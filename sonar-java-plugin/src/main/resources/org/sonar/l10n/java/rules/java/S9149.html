Why is this an issue?

Method hiding occurs when a subclass defines a static method with the same signature as a static method in its superclass. Unlike instance method overriding, static methods are resolved at compile time based on the declared type of the reference, not the actual runtime type of the object. This behavior is counterintuitive and can lead to subtle bugs.

When a variable is declared as the parent type but holds a child instance, calling a hidden static method through that variable invokes the parent's version, not the child's. This contradicts the polymorphic behavior developers expect from instance methods.

Noncompliant code example

class Parent {
    static void calculate() {
        // Parent implementation
    }
}

class Child extends Parent {
    static void calculate() {  // Noncompliant
        // Child implementation
    }
}

Compliant solution

class Parent {
    static void calculate() {
        // Parent implementation
    }
}

class Child extends Parent {
    static void calculateExtended() {
        // Child implementation
    }
}
