An issue is raised when a literal value (numeric, boolean, or other primitive) is converted to a string by concatenating it with an empty string rather than using explicit conversion methods.

Why is this an issue?

Converting literals to strings by concatenating them with empty strings is an inefficient and unclear approach.

When you write an expression that concatenates an empty string with a non-string value, the language runtime must:

  • Create a string building object or buffer
  • Append the empty string
  • Append the value after converting it to a string
  • Call a method to extract the final string result

This creates unnecessary intermediate objects and performs extra operations. More importantly, the intent is unclear - a developer reading an empty string concatenated with a value must infer that this is a type conversion, rather than seeing an explicit conversion call.

Most languages provide explicit, efficient methods for converting primitives to strings:

  • Type-specific conversion functions (e.g., functions that convert integers to strings, booleans to strings)
  • Generic conversion functions that accept any value type

These methods directly convert the value to a string without unnecessary intermediate steps, making both the intent and the operation clearer.

In Java, these explicit methods include Integer.toString(), Boolean.toString(), and other type-specific methods, or the generic String.valueOf() method.

What is the potential impact?

The performance impact of using string operations as an indirect method for type conversion is typically small in individual cases, but can accumulate in large applications or performance-sensitive code paths. More significantly, this pattern reduces code readability and maintainability by obscuring the developer’s intent.

How to fix it

Replace empty string concatenation with explicit type conversion methods. For primitive types, use the wrapper class’s static toString() method (e.g., Integer.toString(), Long.toString(), Boolean.toString()). Alternatively, use String.valueOf() which works for all types.

Code examples

Noncompliant code example

String s = "" + 123;   // Noncompliant
String b = "" + true;  // Noncompliant
String f = "" + 3.14f; // Noncompliant

Compliant solution

String s = Integer.toString(123);
String b = Boolean.toString(true);
String f = Float.toString(3.14f);
