Enabling extensions on Apache XML RPC configuration objects activates support for serializable Java objects, which can lead to remote code execution through deserialization attacks.

Why is this an issue?

The Apache XML RPC library implements the XML-RPC protocol. By default, the library supports a standard set of data types defined in the protocol specification. However, the library also provides optional extension types that are disabled by default for security reasons.

When you enable extensions by calling setEnabledForExtensions(true), you activate the <ex:serializable> type that allows Java object serialization. This means an attacker who can send requests to your endpoint can craft a malicious serialized object and trigger arbitrary code execution when the server deserializes it.

What is the potential impact?

An attacker who can send requests to your XML RPC endpoint can achieve remote code execution on the server. This allows them to:

  • Execute arbitrary system commands
  • Read or modify sensitive data
  • Install backdoors or malware
  • Compromise the entire server and potentially pivot to other systems

How to fix it

Do not enable extensions on your Apache XML RPC configuration. The default behavior (extensions disabled) is secure and sufficient for most use cases.

Code examples

Noncompliant code example

XmlRpcServerConfigImpl config = new XmlRpcServerConfigImpl();
config.setEnabledForExtensions(true); // Noncompliant

Compliant solution

XmlRpcServerConfigImpl config = new XmlRpcServerConfigImpl();
// Extensions are disabled by default - no action needed
