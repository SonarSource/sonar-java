Why is this an issue?

Constructors should not access the values of fields that haven’t yet been initialized.

In Java records, a compact constructor runs before the record components are implicitly assigned to their corresponding backing fields. When a component’s accessor method is invoked on the record instance inside a compact constructor, it reads the uninitialized field rather than the constructor argument, returning its default value (such as null, 0, or false). This can silently corrupt validation logic or lead to unexpected runtime exceptions.

This rule raises an issue when a record component accessor is invoked on the record instance inside a compact constructor.

How to fix it

Reference the constructor parameter directly instead of calling the component accessor method.

Code examples

Noncompliant code example

record User(String name) {
  User {
    if (name().isBlank()) { // Noncompliant: name() is called before the field is initialized and returns null
      throw new IllegalArgumentException("Name cannot be blank");
    }
  }
}

Compliant solution

record User(String name) {
  User {
    if (name.isBlank()) { // Compliant: direct parameter access
      throw new IllegalArgumentException("Name cannot be blank");
    }
  }
}
