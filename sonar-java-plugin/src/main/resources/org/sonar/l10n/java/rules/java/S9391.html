Traditional for or foreach loops that filter elements, transform them, or collect results into a collection can be more clearly expressed using functional collection processing APIs that provide declarative iteration constructs.

Why is this an issue?

Modern programming languages provide declarative, functional interfaces for processing collections. Traditional imperative loops that perform filtering, mapping, or collecting operations can be harder to read and understand at a glance because:

  • The intent is buried in implementation details - readers must trace through the loop logic to understand what the code does
  • Boilerplate code (creating result collections, manual iteration) obscures the business logic
  • The code doesn’t follow modern idioms, making it feel outdated

Common patterns that benefit from declarative collection processing include:

  • Filtering elements based on a condition
  • Transforming elements (mapping)
  • Collecting filtered or transformed elements into a new collection
  • Finding the first element matching a condition
  • Checking if any or all elements match a condition

Declarative collection processing expresses these operations more clearly by:

  • Making the intent explicit through method names like filter, map, and collect
  • Separating the "what" (the operation) from the "how" (the iteration mechanism)
  • Reducing boilerplate code
  • Enabling potential performance optimizations through lazy evaluation

While the traditional loop and declarative version are functionally equivalent, the declarative version communicates intent more directly, making the code easier to maintain and understand.

In Java, this declarative approach was introduced in Java 8 through the Stream API.

What is the potential impact?

This issue affects code maintainability and readability. While it doesn’t introduce bugs or security vulnerabilities, converting imperative iteration constructs to modern functional collection processing APIs:

  • Reduces the cognitive load for developers reading the code
  • Makes the codebase more consistent if you’re following modern language practices
  • Can sometimes improve performance through lazy evaluation and potential parallelization
  • Helps teams working with newer language versions adopt idiomatic patterns

The impact is primarily on developer productivity - code that clearly expresses intent is faster to understand, review, and modify.

How to fix it

Replace the traditional loop with a stream pipeline. Start with collection.stream(), then chain the appropriate intermediate operations (filter, map), and finish with a terminal operation (collect, findFirst, etc.).

Code examples

Noncompliant code example

List<String> result = new ArrayList<>();
for (Item item : items) {
    if (item.isActive()) { // Noncompliant
        result.add(item.getName());
    }
}

Compliant solution

List<String> result = items.stream()
    .filter(Item::isActive)
    .map(Item::getName)
    .collect(Collectors.toList());
