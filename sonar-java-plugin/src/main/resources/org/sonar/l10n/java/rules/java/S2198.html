Why is this an issue?

In Java, primitive numeric types have fixed value ranges defined by the language specification. When you compare a variable of a bounded type against a constant that is outside the type's range, the result is predetermined and the comparison is unnecessary.

For example, a byte variable can only hold values from -128 to 127. Comparing it against 200 will always yield the same result, regardless of the variable's actual value.

These comparisons indicate a logic error, a wrong variable type, or dead code.

How to fix it

Ensure the constant is within the variable's type range, or change the variable to a wider type if comparisons against larger values are needed.

Code examples

Noncompliant code example

byte b = 0;
if (b > 200) { // Noncompliant - always false
    doSomething();
}

Compliant solution

int b = 0;
if (b > 200) { // Compliant
    doSomething();
}
