Why is this an issue?

A NullPointerException should indicate that a null value was unexpectedly encountered. Good programming practice dictates that code is structured to avoid NPE’s.

Explicitly throwing NullPointerException or declaring it in a throws clause suggests that callers should catch it, rather than coding to avoid it. Since NullPointerException is an unchecked exception, declaring it in a throws clause is unnecessary.

If an NPE is being thrown to indicate that a parameter to the method should not have been null, use Objects.requireNonNull() instead. It makes the intent explicit and produces a consistent, descriptive error. Additionally, the parameter can be annotated with @NotNull to document the contract and allow tools to detect violations.

Noncompliant code example

public void doSomething (String aString) throws NullPointerException {
  if (aString == null) {
    throw new NullPointerException();
  }
}

Compliant solution

public void doSomething (@NotNull String aString) {
  Objects.requireNonNull(aString, "aString must not be null");
}
